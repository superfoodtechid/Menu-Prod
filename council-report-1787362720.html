LLM Council Decision

Strategi Mematikan Ubah Harga pada Item Promo / Diskon (GoFood, GrabFood, ShopeeFood)

Status: Rekomendasi Disetujui (Multi-layer Lock & Partial C5 Push)

Verdict Summary

Pengubahan harga dasar pada menu yang sedang berstatus Promo / Slash Price wajib dikunci pada UI dan disaring pada level worker backend untuk mencegah kegagalan massal (API rejection 400/409) pada portal GoFood, GrabFood, dan ShopeeFood.

Arsitektur Penguncian Multi-Layer

  • Layer 1 - UI Form (Single & Bulk Edit): Input harga didisable (disabled={item.is_in_promo}), checkbox multi-select dinonaktifkan, dan bulk formula (+Rp/%) otomatis mengabaikan item promo.
  • Layer 2 - Backend Request Validator: Endpoint push harga mendeteksi flag promo dan memfilter keluar item terkait sebelum masuk antrian.
  • Layer 3 - Partial C5 Push Engine: Pada C5 push, perubahan nama/foto/kategori tetap berjalan, sedangkan perubahan harga diskip dengan audit trail SKIPPED_ACTIVE_PROMO.

Advisor Stances

The Contrarian

UI disabled saja tidak cukup; backend wajib memvalidasi agar script API tidak melempar error 400 ke portal aplikator.

The First Principles Thinker

Base price adalah pondasi kalkulasi diskon portal. Mengubah base price saat promo merusak integritas diskon.

The Expansionist

Terapkan Partial Field Push agar update foto & nama tetap berhasil walau harga item promo terkunci.

The Outsider

Berikan badge "PROMO AKTIF" dan tooltip jelas agar staf resto mengerti alasan harga tidak dapat diedit.

The Executor

Pasang penguncian konsisten di EditHargaTab.jsx, ShopeeEditHargaTab.jsx, dan main.py.

Lihat Detail Langkah Eksekusi
  1. Periksa EditHargaTab.jsx dan ShopeeEditHargaTab.jsx untuk memastikan is_in_promo mengunci input harga.
  2. Pastikan bulk price adjust (penambahan nominal / persen) otomatis mem-bypass item dengan is_in_promo === true.
  3. Pastikan main.py pada endpoint /api/jobs/push-price dan background runner memvalidasi / menskip item promo.
