LLM Council Report

Implementasi Upload Link Google Drive C5 pada Menu Push

Pertanyaan: Pengimplementasian Menu Push C5 via link GDrive selain file fisik XLSX.

Chairman's Verdict

Rekomendasi: Dual-Input Ingestion Layer (Stream Fetcher)
Core parsing engine (openpyxl + diff logic) tidak perlu diubah. Tambahkan modul downloader di backend untuk mengubah link GDrive / GSheets menjadi bytes buffer secara langsung, lalu salurkan ke pipeline parsing yang sama.

Kesepakatan & Arsitektur Solusi

  • Frontend (MenuPushTab.jsx): Tambahkan segmented switch: [Upload File] | [Link Google Drive]. User tinggal menempelkan URL sheet / file C5.
  • Backend (main.py): Endpoint /api/jobs/parse-c5 menerima file: Optional[UploadFile] atau drive_url: Optional[str].
  • Ekstraksi ID & Download Stream: Ekstrak ID dari /d/{ID}/, lalu unduh format XLSX melalui direct export endpoint Google (https://docs.google.com/spreadsheets/d/{ID}/export?format=xlsx atau https://drive.google.com/uc?export=download&id={ID}).
Next Step: Buat helper fetch_gdrive_bytes(url) di backend dan perbarui parameter /api/jobs/parse-c5.

Detail Advisor

The Contrarian
Masalah utama adalah izin berkas (private) dan live edits. Wajib ada error handling 403 yang jelas dan snapshot stream sebelum parsing.
The First Principles Thinker
Input file atau link hanyalah pintu masuk. Keduanya harus menghasilkan byte buffer data C5 yang identik sebelum masuk ke core diff logic.
The Expansionist
Memungkinkan workflow tanpa perlu download lokal berulang kali, membuka integrasi sync massal per brand.
The Outsider
User sering menempel URL format acak (view/edit/folder). Regex harus tangguh mengekstrak ID berkas secara otomatis.
The Executor
Gunakan native direct export HTTP stream tanpa setup OAuth berat. Cukup butuh ~30 baris kode di FastAPI backend dan penambahan tab di React.
