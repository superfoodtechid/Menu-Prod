Titik Rentan & Rekomendasi Mitigasi

  • Isolasi Proses Browser: Setiap iterasi per-merchant wajib membungkus proses Chromium dalam blok try...finally dengan pemanggilan proc.kill() eksplisit untuk mencegah OOM-kill saat memproses puluhan cabang.
  • Atomic Audit Commit: Catat record AuditTrail seketika setiap 1 item berhasil di-patch ke GoBiz, bukan menunggu seluruh batch selesai.
  • Batas Proteksi Google Drive: Batasi ukuran file download maksimal 20MB dan batas waktu 30 detik untuk mencegah eksploitasi server.
Langkah Prioritas: Pastikan fungsi _push_c5_gofood_for_merchant membersihkan subprocess Chromium 100% pada kondisi error apapun.

Analisis Detail 5 Advisor

1. The Contrarian (Failure Modes)
Jika operator upload 1 file C5 berisi 30 SID sekaligus, Playwright akan membuka 30 browser context secara beruntun. Satu error tak tertangani bisa meninggalkan proses zombie Chromium yang menghabiskan seluruh RAM host.
2. The First Principles Thinker (Integritas Data)
Audit trail tidak boleh hanya di-commit di akhir job. Kegagalan koneksi di item ke-70 dari 100 akan membuat job berstatus FAILED tanpa penanda item mana yang sudah sukses masuk ke server merchant.
3. The Expansionist (Skalabilitas)
Global platform lock saat ini membatasi throughput sistem menjadi serial murni. Untuk menangani ratusan toko per jam, kunci harus di-shard per email akun login.
4. The Outsider (UX & Resiliensi)
Operator butuh progress bar spesifik tingkat item (misal: "Mengupdate item 14/40: Paket Hemat...") agar tahu sistem tidak macet saat request lambat.
5. The Executor (Checklist Tindakan)
1. Bungkus Playwright dengan sub-process killer agresif.
2. Set size limit Google Drive download 20MB.
3. Commit status per-item realtime ke database.
